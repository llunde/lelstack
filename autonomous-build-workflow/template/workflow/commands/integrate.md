# integrate

Role: Orchestrator. Run for each finished worktree unit (build.md §2 step 3). Integrate one unit at a time, in the order units finish (the Contract has already landed).
1. **Rebase** the unit branch onto the current integration branch HEAD, inside the unit's worktree. Conflicts surface there, never in the main checkout.
2. **Resolve conflicts.** Resolve trivial ones yourself (e.g. both sides added unrelated lines). Otherwise dispatch a Resolver (strong / medium) into the worktree with both units' plans and slice notes, and the conflicting hunks. Brief: "Load the `caveman` and `ponytail` skills. Resolve so that both intents hold, with the smallest resolution that does. If they contradict, don't guess: abort the rebase and report the contradiction." On a reported contradiction, run `git rebase --abort`, discard the unit's worktree and branch, and re-dispatch that slice in a fresh worktree from the updated HEAD, one rung up (build.md §1), with the contradiction noted in its brief. If it contradicts again, log a question with a default and run the slice sequentially after the others.
3. **Check** in the worktree: apply the unit's requested shared edits there and commit them to the unit branch, then run `check` on the rebased result. A failure goes back to the unit's Executor once, with the specifics (from a Helper's failure triage if the output is long).
4. **Review** the unit at its plan's level, as in build.md §2 step 5, inside the worktree, with the skill's target `<integration branch>..HEAD`. Because this happens after the rebase, any conflict resolutions are reviewed too. A fix round happens in the worktree and is followed by `check` again. Findings go in the unit's note.
5. **Merge.** On the integration branch, in the main checkout: `git merge --squash <unit branch>`. Turn its proposed entries into real IDs (build.md §5) in the same commit. Commit `<type>(<scope>): <subject> (plan NNN)`.
6. **Clean up.** `git worktree remove <path>`, `git branch -D <unit branch>`, and drop the "In flight" row.
